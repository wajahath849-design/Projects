# Validation report

Run date context: fixed reporting as-of **2026-09-30**. All data and results are **synthetic demonstration data**.

The source generator produced 40 projects, 6 departments, 6 cost categories, 12 fictional clients, 9 fictional managers, 100 budget-allocation rows across 50 versions, 6,635 raw cost rows, and 656 recognized-revenue rows. Four deliberately invalid cost rows were quarantined: one duplicate transaction ID, one blank project identifier, one unknown category, and one transaction before the project start. The curated actual-cost fact contains 6,631 rows, including valid negative corrections. The forecast fact contains 1,431 monthly scenario rows across two snapshots.

The refresh report records zero differences for selected approved budget, actual cost, and recognized revenue reconciliations. The optional SQLite financial view independently returned budget **$36,417,000.00**, actual cost **$31,128,158.99**, and recognized revenue **$40,638,135.28**, matching the curated project extract. `pytest -q --basetemp .pytest_tmp` returned **13 passed** in the local bundled Python runtime. These tests cover CSV schema failure, Excel extraction parity, invalid/missing identifiers and dates, duplicate quarantine, negative corrections, referential integrity, budget version selection, reconciliation, variance/margin/forecast identities, scenario semantics, output columns, idempotent hashes, and forecast nonleakage.

For June 2026 snapshots evaluated against later observed months, the mean absolute error of the **per-project holdout total** is **$10,530.20**. See `reports/forecast_holdout.csv` for each project. This is a narrow retrospective check using one holdout window; it does not establish future accuracy, and the forecast does not model staffing changes, change orders, or uncertainty intervals. The dashboard should show this limitation near forecast visuals.

The final profitability table displayed percentage-formatted project margins. The report's seven pages and 71 visuals also passed `python -m scripts.validate_pbir`, including source-field checks and cost, revenue, profit, forecast, and audit reconciliation.

This Desktop visual check covers the presentation model's seven-page layout and interactions.
