# Power BI report build guide

An editable seven-page report is included at `powerbi/Financial Project Performance.pbip`. Open it in Power BI Desktop and refresh when prompted. It carries an embedded, fixed synthetic reporting snapshot made from the reconciled `ProjectMetrics.csv` extract and six compact marts created by `python -m scripts.build_pbir`. Its pages have native Power BI cards, charts, tables, a project selector, a restrained navy-and-teal theme, and visible as-of and synthetic-data footers. The project selector cross-filters page 6. This file is a presentation model; the fuller model and interactions below are a production extension blueprint.

For that extension, use `powerbi/theme/finance_theme.json`, create `CuratedFolder` and `ReportFolder` parameters, add the Power Query queries, set the relationships in `docs/data_model.md`, mark `DimDate` as the date table, then create the DAX measures from `powerbi/dax/measures.dax`. Format monetary measures as USD with two decimals, rates as percentages with one or two decimals, and negative budget variance in red. Set slicers to single direction filtering. Use the as-of date prominently.

Use a 16:9 canvas, off-white background, navy labels, teal for neutral values, green for favorable variance, amber for forecast risk, and red for actual overruns. Keep KPI cards across the top, trends in the middle, and an actionable project table below. Provide tooltips showing project, selected budget version, actual, forecast, and source date. Global slicers: client, manager, project status, year-month; scenario slicer belongs on the forecast page. The lifetime cards deliberately ignore date slicers; label them `Lifetime through 30 Sep 2026` to prevent confusion. All visuals should display **Synthetic demonstration data** in a small footer.

| Page | Visual configuration and required fields/measures | Interaction |
|---|---|---|
| 1. Executive financial overview | Cards: approved lifetime budget, actual lifetime cost, recognized lifetime revenue, gross lifetime profit, gross margin, budget variance. Combo trend: `DimDate[year_month]` with period cost and period revenue. Bar: top/bottom projects by gross margin. Table: project, health, EAC, forecast overrun. | Project table drills to page 6; cards retain lifetime meaning. |
| 2. Budget vs. actual | Matrix: project and department, approved lifetime budget, actual lifetime cost, variance, utilization. Line/column: `DimDate[month_start]`, `Approved Budget As of Date`, `Actual Cost Period` (label the budget as a stock, cost as monthly flow; use separate axes or two aligned small multiples). Bar: unfavorable projects sorted by negative variance. | Filter by department/project; click a project for transactions. |
| 3. Project profitability | Cards: lifetime recognized revenue, gross profit, weighted margin. Scatter: project revenue vs cost, size by budget, color by health. Trend: period revenue and period cost, plus period margin on separate panel. Project table ranked by lifetime profit and margin. | Drill to page 6; blank margins for zero revenue. |
| 4. Expense and cost analysis | Horizontal bars: `DimDepartment[department_name]` and `DimCostCategory[category_name]` using period cost. Line: monthly actual cost. Stacked monthly bars by cost group. Detail table: transaction ID, date, project, department, category, signed amount. | Cross-filter bars; preserve negative corrections in detail. |
| 5. Forecast and financial risk | Cards: base ETC, EAC, sum of per-project overrun, at-risk count. Project scatter: utilization vs EAC/budget. Line: monthly actual cost through Sep 2026 and future `FactForecast[forecast_cost_usd]` after Sep. Scenario comparison: selected `FactForecast[scenario]`, `Scenario EAC`. Risk queue sorted by forecast overrun. | Default scenario base; compare optimistic/downside explicitly, then drill through. |
| 6. Project drill-through | Drill-through field `DimProject[project_id]`. Profile: client, manager, status, delivery completion. Cards: selected budget, actual, revenue, profit, margin, ETC, EAC. Revision table: version, approved date, department allocation. Monthly cost/revenue trend, category breakdown, transaction table. | Enable keep-all-filters; transaction ID links source row in raw CSV. |
| 7. Data quality and reporting audit | Cards: last refresh/as-of from `refresh_report.json`, rejected row count, source row count, reconciliation deltas, holdout MAE. Tables: exception reason/source/row/record, manifest filename/hash/rows, forecast holdout per project. | Show source freshness and any nonzero reconciliation in red; audit tables stay disconnected. |

For actual versus forecast on page 5, use two measures on the same month axis: `Actual Cost Period` for dates through 2026-09-30, and a forecast-month sum filtered to latest base snapshot for later months. Suppress the other series outside its valid range using a visual date filter or explicit DAX `IF` wrapper. Forecast scenarios should use an explicit single-select scenario slicer; the `Scenario Forecast Cost` measure defaults to base when none is selected.

Desktop QA for the included PBIP: compare page 1 lifetime cards against `ProjectMetrics.csv` totals and `reports/refresh_report.json`; use page 6's project selector for P001, P002, and P003; confirm page 7 shows four rejected rows and zero reconciliation deltas. To change the snapshot, rerun the pipeline and `python -m scripts.build_pbir`, then reopen and refresh the PBIP. The extended star-schema design would additionally require relationship, budget-version, scenario-slicer, and drill-through tests before production use.
